# cloudflare-zero-trust-tunnel-routes

OpenTofu module for `cloudflare zero trust tunnel virtual networks and private-network routes`.

## Requirements

| Provider | Source | Version |
| --- | --- | --- |
| `cloudflare` | `cloudflare/cloudflare` | `>= 5.22.0` |

## Usage

Releases are cut per module by release-please. Each release publishes an orphan tag
whose root **is** this module, so no `//<subdir>` selector is needed:

### Terragrunt

```hcl
terraform {
  source = "git::https://github.com/kholisrag/iac-modules.git?ref=cloudflare-zero-trust-tunnel-routes/v0.1.0"
}
```

### OpenTofu / Terraform

```hcl
module "cloudflare_zero_trust_tunnel_routes" {
  source = "git::https://github.com/kholisrag/iac-modules.git?ref=cloudflare-zero-trust-tunnel-routes/v0.1.0"
}
```

Floating tags `cloudflare-zero-trust-tunnel-routes/v0` and `cloudflare-zero-trust-tunnel-routes/v0.1` track the latest matching release.

## Things that bite

**The tunnel is referenced, not owned.** Pass `tunnel_id`; this module never
creates or destroys a tunnel, so it is safe to point at one that another stack
(or the dashboard) owns.

**A route only works if the connector can reach the CIDR.** Cloudflare accepts
any CIDR on any tunnel. If `cloudflared` sits behind a NAT that hides the
range, the route is published and dead.

**Map keys are labels, not CIDRs.** Keys show up in plan output and state
addresses; keep topology in values, which a consumer can source from an
encrypted file.

**Every account has an autogenerated `default` virtual network.** Import it
rather than declaring a second default.
